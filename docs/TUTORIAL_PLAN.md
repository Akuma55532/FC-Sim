# FC-Sim 使用教程编写计划

## 1. 教程目标与范围

让了解基本 Linux 命令、尚不熟悉本项目的使用者，从环境准备开始，完成一次单机 PX4 仿真飞行：启动系统、确认状态、起飞、执行航点、停止或降落，并能根据状态定位常见问题。

默认教学环境采用现有文档声明的 Ubuntu 22.04、ROS 2 Humble、MAVROS 2.16.0、PX4 v1.17.0-beta1 和 Gazebo `gz_x500`。这些是教程拟采用的基线，具体 Gazebo 版本及整套兼容性需要实测后记录。

主线覆盖当前实现的单机 MAVROS/PX4 后端和 RViz2 面板。多机、实机部署、避障、轨迹规划及其他飞控后端留作后续主题；当前仓库不构成这些能力的完整教程依据。

已有材料需要解决的断点：

1. `docs/` 原为空，包内 README 引用了不存在的快速开始、状态参考、排障和开发文档，部分相对路径也不符合当前目录层级。
2. 根 README、MAVROS 说明、面板说明分别使用 `~/ws_sim`、`~/ws_simulator` 和旧 `flight_ws` 路径，缺少统一的目录约定。
3. 安装脚本实际写入 `~/mavros_humble_ws`；仓库内的 `pkgs/mavros_humble_ws/` 当前为空，不能作为已有安装使用。
4. 缺少从源码构建本项目三个 ROS 包、逐终端加载环境、按顺序启动和验收的连贯流程。
5. MAVROS 说明中的直接启动示例与项目的 `mavros_gcs.launch.py` 面向不同使用场景。项目教程应统一使用项目入口，并说明 GCS 心跳配置。
6. 现有测试源码可以提供验证场景，但不能代替实际 Gazebo/PX4 飞行验收记录。

## 3. 系统关系与学习顺序

```mermaid
flowchart LR
    U[用户：ROS 2 命令行 / RViz 面板] -->|Action / 服务| C[flight_core]
    C -->|控制目标 / 模式与解锁请求| M[MAVROS]
    M <-->|MAVLink| P[PX4 SITL + Gazebo]
    M -->|遥测| C
    C -->|ControlStatus / Action 反馈与结果| U
```

先解释每个进程负责什么，再让读者完成可观察的小步骤。RViz 是操作入口，`flight_core` 负责动作和持续目标输出，MAVROS 连接 PX4。读者不需要先通读 MAVROS 全部接口才能开始使用。

## 5. 首次飞行章节的具体设计

### 前置条件

- 已完成安装和编译，记录实际 PX4、MAVROS、ROS 和 Gazebo 版本。
- 统一目录变量：`FC_SIM_ROOT` 指向仓库，`PX4_ROOT` 指向 PX4 源码，MAVROS 安装遵循脚本的 `~/mavros_humble_ws`。
- 拟采用在仓库根目录执行 `colcon build --base-paths pkgs/flight_pkgs --symlink-install` 的构建方式；正文发布前验证依赖与产物路径。
- 每个 ROS 终端按顺序加载 ROS、MAVROS、本项目 overlay，并使用相同 ROS 域。PX4 终端单独列出。

### 操作步骤与观察点

1. 启动 PX4/Gazebo：拟使用 `make px4_sitl gz_x500`；确认模型出现及飞控启动日志。
2. 启动 MAVROS：使用 `ros2 launch flight_core mavros_gcs.launch.py`；说明默认 UDP 地址与 `fcu_url` 覆盖方式。
3. 检查 MAVROS 的连接、状态、地面状态和本地位姿；需要时用 `mavlink status` 核对端口。
4. 启动核心：`ros2 launch flight_core basic_actions.launch.py`；检查 `/flight_core/control_status` 和 Action 列表。
5. 发送 1 m 相对高度起飞目标；正文给出完整 `ros2 action send_goal` 命令和反馈示例。
6. 等待 Action 成功，并观察核心进入保持；解释当前高度与起飞相对高度的区别。
7. 使用 `/flight_core/land_action` 降落；等待最终结果并确认地面和解锁状态。
8. 飞行收尾完成后再关闭进程；另列异常中断时应检查的状态。

主线先通过命令行验证链路，下一章复用同一套运行环境打开面板。起飞流程由核心组织模式切换与解锁，不要求读者在旁路终端手工重复发送 MAVROS 控制请求。

## 6. 必须讲清楚的现有行为

以下内容已静态对照源码，编写正文时仍需配合运行示例验证。

- **接口名称：**默认 Action 为 `/flight_core/arm`、`disarm`、`takeoff`、`land_action`、`execute_waypoints`；`/flight_core/land` 和 `/flight_core/stop` 是 Trigger 服务，不能混用。
- **相对高度与绝对航点：**起飞 `height_m` 相对于起飞时位置，范围为 `(0, 10]` m；航点是 `map` 下绝对 ENU 坐标。Action 的 yaw 使用弧度，面板和航点 YAML 使用度。
- **任务前提：**执行航点前必须由当前核心建立保持控制，仅看到飞控处于 OFFBOARD 不足以满足要求。
- **航点边界：**最多 500 点；当前位置到首点、相邻点以及循环闭合段均有 10 m 距离限制。到点检查包含 XYZ 距离、可选 yaw 和停留时间。
- **停止有上下文：**航点停止尝试保持当前位置；起飞中的停止触发降落清理；停止服务不是任何状态下都有效的暂停按钮。
- **接受不等于完成：**必须读取 Action 终态、结果码及实际遥测；服务返回成功也不表示已经落地。通过 stop 服务结束任务的终态与 Action cancel 路径需要分别说明。
- **面板独立：**`panel.launch.py` 只启动 RViz。关闭面板不会取消核心已接收的任务；修改草稿不改变已提交的任务快照。
- **参数限制：**核心明确拒绝 `use_sim_time=true`，且禁止运行时修改参数；不能直接套用一般仿真教程的时钟设置。源码中的 Config 常量也不能写成已经开放的 ROS 参数。
- **控制实例互斥：**同机同 ROS 域与 MAVROS 端点已有核心时，第二个实例会拒绝启动。
- **能力边界：**当前航点执行没有避障规划；底层直发 MAVROS 控制示例应放在独立实验中，避免与核心持续控制同时使用。

## 7. 每章写作模板

每章统一包含：学习目标、前置条件、终端及工作目录、可复制的命令、关键预期输出、成功判据、常见失败及恢复方法、下一章入口。

输出示例区分“实际采集”和“字段示意”。控制命令写明执行条件；不能只给命令而不说明读者应等待什么结果。截图用于说明面板位置，关键状态同时保留文本说明。

## 8. 编写与验证顺序

1. **第一阶段：打通最短路径。**先写概览、安装、构建和快速开始，统一路径与版本。在实际 SITL 中记录一次起飞—保持—降落，之后更新根 README 入口。
2. **第二阶段：完成日常使用。**编写面板与航点章节，提供短距离航点文件，验证单步、全部、停止和保存加载。
3. **第三阶段：补全解释和接入。**编写状态参考、ROS API 与排障，客户端示例显式处理 Action 被拒绝、执行失败及遥测过期。
4. **第四阶段：维护与回归。**整理开发测试文档，修复包 README 的历史链接；检查所有相对链接，并由未参与开发的读者按正文复现。

教程发布前至少记录：版本、启动命令、ROS 域/命名空间、起飞及降落结果、多点任务结果、停止后的实际状态、面板失联表现。逻辑测试、假服务测试和真实 SITL 验收分别记录，不能互相替代。
